# Контракт backend ПСБ

Статус HTTP API и интерфейса ML2 — черновик для согласования с командой. Платформенный контракт основан на [регламенте, §§ 2–7](https://docs.google.com/document/d/1GjOSBr6xtiweDrMI5Kvcnug4wcbHCzg7n5TJ4UBnuxg/edit) и [стартере](https://drive.google.com/file/d/1r0JktdUAQrKZ7fnc60df6GJxsHgBd0jx/view).

## Платформа → backend → CSV

- `solution.py` читает `DATA_DIR/questions.csv` и `DATA_DIR/knowledge-base.zip`. По умолчанию каталог — `data`. Входной CSV имеет колонки `id,question`. На чтении поддерживается UTF‑8 с BOM и без него.
- В демонстрационных диалогах `question` содержит многострочный текст с префиксами `Пользователь:` и `Ассистент:`. Backend передаёт генерации последнюю пользовательскую реплику и предшествующие сообщения. Одиночный вопрос имеет пустую историю. Каждый ID обрабатывается независимо.
- Некорректный заголовок, нарушение структуры CSV, пропущенный или повторяющийся ID и пустой файл завершают запуск с диагностикой. Вопрос из пробелов при наличии валидного ID получает запрос на уточнение. Нечитаемая база и отсутствующая конфигурация генерации останавливают запуск до записи результата.
- `submission.csv` записывается целиком в текущий рабочий каталог в UTF‑8 без BOM с колонками `id,answer` и стандартным CSV-экранированием. Исходные ID и порядок сохраняются. Метки ML2 вида `[E1]` заменяются ссылками `[1]` на нумерованный список процитированных положений из ML1. Лимит в 10 000 символов проверяется вместе со ссылками.
- Отказ прокси, тайм-аут, некорректный ответ модели и незавершённый случай при исчерпании общего бюджета получают техническое сообщение без юридических выводов. Счётчики ошибок печатаются без вопросов, документов и секретов. Для обработки зарезервировано 19 минут из 20, включая подготовку и отмену запросов.
- Сборщик кладёт в ZIP `solution.py`, `psb_backend.py`, опубликованный автономный `retrieval_runtime.py`, платформенный `requirements.txt` и корневые модули ML2 со встроенным промптом. Для преобразования исходников и промпта переиспользуются функции командного сборщика ML2. Индекс строится из полученной базы. Порог сборщика — 128 000 000 байт, дневная квота команды — 5 попыток.

## Backend ↔ ML1 ↔ ML2

Backend строит локальный индекс один раз через ML1 и вызывает `Retriever.search_with_diagnostics(query, top_k, history)` для каждого вопроса. В первом сабмите используются BM25 и локальный символьный TF‑IDF. Внешние эмбеддинги и реранкинг отключены. [Контракт ML1](https://github.com/Koomaz/PSBcase-bablteam/blob/78fa556e97a10ebf016ee630239f0920b42495e8/ML1/reports/retrieval_report_for_ML2.md#L5)

Backend передаёт нормализованный вопрос, историю, чанки и диагностику в `LegalAssistant.answer_prepared`. Это вход в тот же конвейер ML2, что использует его CLI. ML2 собирает доказательства и соседние фрагменты, формирует сообщения, вызывает модель, проверяет результат и при необходимости делает повторную генерацию. История передаётся отдельно как данные диалога.

- ML2 отдаёт текст, метки `[En]`, соответствие меток `chunk_id` и результат валидации. Backend заменяет метки на `[1]`, `[2]` в порядке `sources`, разрешает ID только среди текущих фрагментов и их соседей и подставляет оригинальные метаданные ML1.
- Если валидация ML2 после повторной попытки не пройдена, backend возвращает техническую ошибку. CLI ML2 сохраняет собственное поведение. Классификация ML2 позволяет различать ответ и отказ. Backend также выделяет недостаточность данных при отказе без источников. Отдельных машинных статусов для частичного ответа и уточнения ML2 пока не возвращает.
- Транспорт backend использует точный базовый URL из регламента и отменяемый запрос. При `429`, `5xx` или сетевом сбое выполняется максимум один повтор на HTTP-вызов, в пределах общего бюджета генерации на вопрос. На ошибки авторизации повтор не выполняется.
- Нужны адрес, ключ и идентификатор модели из окружения. При отсутствии настроек, ML2 или промпта сервис недоступен. Встроенный mock из CLI ML2 не используется. Тестовые имитации находятся в `tests/` и не входят в ZIP.

## Backend ↔ фронтенд

| Метод | Вход | Результат |
|---|---|---|
| `GET /health/ready` | — | `200 {"status":"ready"}` при загруженной базе и настроенном адаптере или `503`. Вызова к модели нет. |
| `POST /api/chat` | `{"question":"…","history":[{"role":"user","content":"…"},{"role":"assistant","content":"…"}]}` | `200 {"kind":"…","answer":"…","sources":[…]}`. История необязательна. Текущий вопрос передаётся отдельно. |
| `GET /api/sources/{chunk_id}` | ID из `sources` | Метаданные источника и дословный `text` либо `404`. |

Вопрос и реплики имеют до 4 000 символов. История принимает до 8 сообщений, суммарно до 12 000 символов. Роли только `user` и `assistant`. Backend не ведёт сессии. Для отдельных origin фронтенда можно задать список `PSB_CORS_ORIGINS` через запятую.

Метки в тексте начинаются с `[1]` и соответствуют порядку массива `sources`. В каждой ссылке есть `chunk_id`, `doc_id`, `doc_title`, `source_reference`, путь в корпусе и символьные границы `[char_start, char_end)`. Пункт, статья, редакция, даты и временной статус берутся из ML1, где они доступны. Временной статус в ответе чата относится к вопросу. У отдельного фрагмента он может быть пустым. За текстом фронтенд обращается по `chunk_id`. Путь в корпусе не принимается как параметр доступа к файлу.

Ошибки API возвращают `{"detail":{"code":"…","message":"…"}}`. Основные статусы — `422 invalid_request`, `503 unavailable`, `502 upstream` или `invalid_response`, `504 timeout`, `404 source_not_found`, `500 internal`. Неожиданный сбой локального поиска также переводится в `503 unavailable`, чтобы не раскрывать внутренние детали.

## Конфигурация

| Переменные | Назначение |
|---|---|
| `DATA_DIR` | Каталог базы и платформенного CSV. По умолчанию `data`. |
| `LLM_BASE_URL` / `OPENAI_BASE_URL` | Адрес прокси, включая его базовый путь. |
| `LLM_API_KEY` / `OPENAI_API_KEY` | Ключ прокси из окружения. |
| `LLM_MODEL` / `OPENAI_MODEL` / `GEN_MODEL` | Идентификатор генеративной модели из окружения. |
| `TOP_K`, `MAX_WORKERS` | По умолчанию 5 фрагментов и 2 одновременных вызова. |
| `TEMPERATURE`, `MAX_TOKENS` | По умолчанию 0 и 1 024. |
| `PSB_REQUEST_TIMEOUT` | Суммарный бюджет генерации на вопрос, включая повтор. По умолчанию 25 секунд. |
| `PSB_CORS_ORIGINS` | Разрешённые origin чата. |

Внешние URL документов не используются для генерации. API рассчитан на локальный прототип и доверенную среду команды. Авторизация и публичное развёртывание относятся к следующему этапу.

## Граница времени и ссылки

Бюджет 19 минут учитывает время подготовки и поиска, однако синхронная сборка индекса и поиск ML1 не прерываются таймером Python. Перед каждым следующим случаем проверяется остаток бюджета. Сетевые вызовы отменяются по тайм-ауту. Жёсткий предел процесса задаёт платформа. Локальные замеры относятся к предоставленному корпусу из 21 документа.

Числовые метки `[1]` зарезервированы за backend. Если модель прислала такую метку вместо формата ML2 `[En]`, результат отклоняется, чтобы ссылка не могла обойти проверку источника.

Веб-чат и новый корневой ZIP используют общий транспорт и ML2. `ANSWER_REVIEW=1` включает дополнительный редакторский проход ML2 в обоих режимах. По умолчанию он выключен до проверки задержек реального прокси. Бюджет `PSB_REQUEST_TIMEOUT` охватывает все попытки и редактуру одного вопроса. В автономном CLI ML2 собственные значения по умолчанию, поэтому его результаты не считаются эквивалентными корневому сабмиту без сверки конфигурации.
