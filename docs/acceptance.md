# Продуктовая приёмка

Таблица предназначена для проверки содержания, полноты и применимости ответов юридического ассистента. Основа — 18 вопросов из [демонстрационного набора](../ML1/demo_questions.csv), образец `demo_output.csv` и положения `knowledge-base.zip` из [материалов организаторов](https://drive.google.com/drive/folders/1lendasLVlcKUcuM8mOrWKHD-C2dWtm9F).

Ожидаемые результаты сверены с предоставленной базой знаний. Проверяется смысл ответа, выбранный источник и применимая редакция; допустимы равнозначные формулировки. Результат программного валидатора и продуктовая оценка фиксируются отдельно.

Команды локального прогона приведены в [корневом README](../README.md#локальный-прогон). Для продуктовой приёмки используйте рабочую модель и сохраните фактический набор доказательств, переданный ей для каждого вопроса. Текущая трассировка ML2 хранит ID ссылок, число доказательств и диагностические поля; полный набор документов и фрагментов приложите к материалам прогона отдельно. Прогон с заглушкой фиксируется как техническая проверка конвейера.

## Как заполнять

1. Укажите данные прогона и перенесите фактические ответы из `submission.csv` в строки с соответствующим `id`. Для диалогов проверяется ответ на последнюю реплику с учётом всей переданной истории.
2. Сверьте вывод, числовые значения, сроки, полноту ответа и применимость источника по дате. Каждое юридически значимое утверждение сопоставьте с положением из базы.
3. Сопоставьте ссылки `[En]` с фактическим набором доказательств конкретного запроса: должны совпадать документ, пункт или статья и подтверждающий текст.
4. В последней колонке укажите статус и замечание. Для ошибки приложите ссылку на задачу, ожидаемый результат и подтверждающее положение.

Статусы: **принято** — выполнены ожидаемые условия; **частично** — требуется дополнить подтверждённый ответ; **ошибка** — неверный вывод, источник, факт или реакция; **ожидает проверки** — оценка фактического ответа предстоит. Знак «—» обозначает поле для заполнения.
