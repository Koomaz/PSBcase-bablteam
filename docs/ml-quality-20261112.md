# ML: пакеты доказательств и обязательная семантическая проверка

Реализованы направления из таблицы «Как разделить следующую работу». Кандидат улучшает локальное покрытие источников и закрывает воспроизведённый обход reviewer. Рост private score **не проверен**: в среде нет доступа к прокси организаторов и официальному judge. Сабмит на платформу не отправлялся.

## Изменения

| Направление | Реализация |
| --- | --- |
| ML1: короткие договоры | Только однозначно определённый договор; дословные положения, связанные допсоглашения, исключение реквизитов, ограничения размера. |
| ML1: регламент | Расширение короткой применимой редакции, сохранение исторической/сравнительной применимости, общих правил и исключений. |
| ML1: длинные статьи | Ранжированные части, родительские условия подпунктов; компактные семьи пунктов/короткие статьи целиком в пределах бюджета. Длинный кодекс целиком не передаётся. |
| ML1 + backend | Расширение до построения allowlist цитат. ID и исходный текст не меняются. Отдельный DOCUMENT-заголовок сокращает повтор метаданных. |
| ML2: reviewer | Проверка действия, модальности, отрицания, начала срока, величины, исключений, применимости и ссылки каждого тезиса. Негативный вердикт запускает исправление и повторную проверку; отвергнутый черновик не восстанавливается. |
| ML2: достаточность | Reviewer различает sufficient/partial/related_only/contradictory. Тематическая близость не запрещает отказ; подтверждённый частичный ответ передаётся как partial. Короткость не заменяет полноту. |
| Сравнение | Исходный ZIP, исправленная защита без расширения, расширение без semantic review, комбинация. Зафиксированы наборы и скрипты воспроизведения; настоящий модельный прогон подготовлен, но не выполнен. |

Проверки неизвестных ID, чисел и единиц сохранены. Каждое достаточно длинное самостоятельное фактическое предложение должно иметь ссылку; это структурный фильтр, а не самостоятельное доказательство смысла. Семантический reviewer использует ту же модель из окружения; он может ошибаться, поэтому гарантии отсутствия галлюцинаций нет. Некорректный JSON или сбой reviewer закрывает выдачу спорного ответа.

## Локальные результаты

Исходный A — `psb-submission.zip`, SHA256 `4f261db7805e838970714a3be11f15fab6d348bf6bbe96065a5ad7ce1d77940e`. Development: 24 вопроса из исследования. Дополнительный holdout: 10 вопросов с положениями + 4 отрицательных случая, зафиксирован после основной реализации; по его результатам подбор параметров пакета не проводился. Это небольшой внутренний контроль, не независимая оценка организаторов. Темы частично совпадают с development.

| Вариант | Полное evidence на holdout | Среднее покрытие по вопросам | Отрицательные контроли | Scripted semantic checks |
| --- | ---: | ---: | ---: | ---: |
| A: исходный ZIP, review=0 | 5/10 | 78.33% | 4/4 | 2/6 |
| B: новые guardrails, baseline evidence, review=1 | 5/10 | 78.33% | 4/4 | 6/6 |
| C: новый пакет, review=0 | 9/10 | 96.67% | 4/4 | 3/6 |
| D: новый пакет + review=1 | 9/10 | 96.67% | 4/4 | 6/6 |

C включает общий новый структурный валидатор, поэтому это абляция отключением reviewer, а не чистая замена только retrieval относительно A. Evidence у C и D одинаков: генерация начинается после сборки контекста. У B и D одинаковый новый генератор. JSON-результаты находятся в `reports/`.

На development D: 24/24 полных пакета, 100% среднего покрытия (исходное исследование A: 16/24, 88.19%). На holdout D максимальный контекст 6655 символов, на development 6947 при лимите 7000. Медиана локального поиска и упаковки в одном прогоне около 14 мс; это **не** задержка модели/платформы.

Оставшийся неполный holdout — h04: источник допсоглашения не попал в итоговый контекст при ограничении 7000 символов. Метаданные исходного положения остаются, но полный сравнительный пакет не гарантирован. Счётчик `evidence_dropped` показывает такие потери. Нельзя считать packet_route доказательством полноты итогового промпта.

Scripted checks подают заранее заданные корректные/ошибочные ответы и вердикты через настоящий `httpx.MockTransport` в ML2Generator из ZIP. Проверены подмена обязанности, отрицание, начальное событие, утверждение без ссылки и неверная единица. Это проверка исполнения вердикта, **не** измерение способности DeepSeek обнаруживать эти ошибки. D: 2 вызова для корректного ответа, 4 при семантическом исправлении, 2 для повторной локальной блокировки. Новые ID пакета принимаются Service; неизвестные отвергаются.

## Проверки и запуск

- ML1: 16 тестов прошли; локальная база подключена в `ML1/knowledge-base` только для тестирования, в коммит/ZIP она не добавлена.
- ML2: 78 тестов прошли, включая 9 новых проверок обязательного reviewer.
- Пакеты: 4 теста прошли (дословность, неизменность исходного ранжирования, историческая редакция, отсутствие межвопросного состояния, baseline switch).
- Финальный ZIP: все 18 демо-строк, 34 mock-вызова, `failures: {}`. Это интеграционная проверка CSV/модулей/цитат, а не оценка ответов модели.
- FastAPI-тесты и Docker не запущены: отсутствует FastAPI, Docker daemon недоступен. Проверен backend-core через ZIP и MockTransport.

```sh
python ML1/scripts/test_retrieval.py
python -m unittest discover -s ML2/tests -q
python -m unittest discover -s tests -p test_packets.py -q
python scripts/build_submission.py --output dist/psb-submission.zip
python tests/evaluate_evidence.py dist/psb-submission.zip PATH_TO_CORPUS tests/evidence_holdout.json reports/holdout_D.json
python tests/evaluate_semantics.py dist/psb-submission.zip PATH_TO_CORPUS reports/semantic_D.json
python tests/verify_submission.py dist/psb-submission.zip demo_questions.csv knowledge-base.zip
```

Для настоящего A/B/C/D задать **организаторские** LLM_BASE_URL, LLM_API_KEY, LLM_MODEL и вызвать:

```sh
python tests/run_live_ablation.py BASELINE.zip dist/psb-submission.zip questions.csv knowledge-base.zip live_results
```

Скрипт не отправляет сабмиты. Он сохраняет CSV, длительность и логи каждого варианта с теми же вопросами, моделью и температурой 0. Порядок A/B/C/D фиксирован, для устойчивого сравнения нужны повторы с перестановкой порядка. Judge отсутствует: Match Rate, Win Rate, долю ложных отказов, точность ссылок и неподтверждённых тезисов нужно оценить отдельно единым разрешённым способом. Секреты в отчёты не записываются.

## Регламент и риски

В решении только выданная нормативная база; внешних юридических данных и скрытых эталонов нет. Генеративная модель берётся из окружения организаторов. Законы-снимки не дополняются реконструкцией исторических редакций. Метаданные даты, редакции, допсоглашения и comparison_only сохраняются, окончательная применимость проверяется генератором/reviewer.

Сабмит: 16 файлов в корне, только `.py` и `requirements.txt`; единственная зависимость `httpx==0.28.1`, без установки пакетов в solution.py. Тесты, отчёты, база и ключи не упакованы. CSV `id,answer`, независимые ID, максимум 10000 символов сохраняются. Архив существенно меньше 128 МБ. Бюджет batch 19 минут оставляет минуту до лимита платформы 20 минут; отмена/запись CSV остаются в исходном backend.

По умолчанию reviewer включён, лимит 5 логических вызовов на вопрос и внешний timeout 60 секунд. HTTP-повторы входят в общий timeout, но не в счётчик логических вызовов. При медленном прокси больше вопросов может получить технический ответ; измерение реальных задержек и пропускной способности обязательно перед выводом об улучшении балла. Пять суточных попыток платформы не расходовались.
