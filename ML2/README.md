# ML2 — генерация, промпт и guardrails

Превращает выдачу ML1 в ответ по нормативным документам и в `submission.csv`.
Берёт `RetrievedChunk`, нумерует доказательства `[E1]…[En]`, вызывает DeepSeek V4.1 Flash
через OpenAI-совместимый прокси, проверяет ответ и только потом пишет CSV.

```
question → search (ML1) → [E1..En] → system_prompt + <evidence> + <question>
         → LLM (temp=0) → validate → repair-проход → submission.csv
```

## Версия 2: меньше шума, больше опоры на документы

После первого сабмита (11 баллов) конвейер переработан под метрику LLM-судьи:
судья сравнивает ответ с baseline и эталоном, а выдуманный факт обнуляет вопрос.
Поэтому главный приоритет — не длина, а точность и отсутствие лишних утверждений.

Что добавлено:

- **Локальный судья** `scripts/judge_answers.py` по шкале регламента (0 / 0,25 / 0,5 / 0,75 / 1)
  с эталоном `demo_output.csv`; отчёт по каждому вопросу и итоговый Match Rate / Win Rate.
- **Границы ответа** в системном промпте: только элементы того же обязательства, без чужих
  процедур, реквизитов, адресов и повторов; запрет усиливать модальность и выводить новые сроки.
- **Редакторский проход** `llmguard/verifier.py`: проверяет полноту, заземлённость, уместность
  и ссылки; лишнее удаляет по точным фразам, пропущенное добавляет адресно, без свободного
  переписывания. При сбое редактора ответ не ломается.
- **Сравнение редакций** `llmguard/editions.py`: для датированного вопроса к исторической
  редакции подмешивается действующая редакция того же пункта.
- **Детерминированная чистка** `llmguard/postprocess.py`: мета-выводы, повторы, известные
  недоказанные выводы, дубли ссылок, «не сразу», лишние слоты по типу вопроса.
- **Исправлен разбор чисел**: даты вида 10.01.2023 больше не превращаются в 1001 и не
  обнуляют корректный ответ; «12 млн» нормализуется в 12 000 000.
- **Бюджет времени**: после 14 минут редакторский проход отключается, чтобы успеть записать CSV.
- **Локальный поиск по умолчанию**: dense-индекс на старте — это десятки запросов к `/embeddings`,
  которые могут съесть лимит 20 минут. ZIP строит BM25 + TF-IDF за 0,4 с; `RETRIEVAL_DENSE=1`
  включает BGE, если он нужен.

Локальная оценка на 18 демо (судья `gpt-5.4`, эталон `demo_output.csv`):

| Версия | Match Rate | Win Rate | Итог 0,7·MR + 0,3·WR |
| --- | ---: | ---: | ---: |
| до изменений | 0,597 | 0,769 | 0,649 |
| после основных изменений | 0,653 | 0,867 | 0,717 |
| финальная сборка ZIP (local retrieval) | 0,611 | 1,000 | 0,728 |

Судья на 18 вопросах шумит: у похожих формулировок разброс ±0,1. Поэтому финальную
сборку проверяем на платформе, а не только локально. Тесты: 67.

## Быстрый старт

```bash
cd ML2

python3 solution.py --questions ../ML1/demo_questions.csv --data-dir ../ML1   # боевой прогон
MOCK_LLM=1 python3 solution.py --questions ../ML1/demo_questions.csv \
    --data-dir ../ML1 --out submission_mock.csv          # без сети, на заглушке
python3 -m unittest discover -s tests -v                 # 67 тестов guardrails
```

Ключи читаются из `ML2/.env` (в `.gitignore`) или из окружения:

| Переменная | Смысл | По умолчанию |
| --- | --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | прокси модели | — |
| `LLM_MODEL` (`OPENAI_MODEL`, `GEN_MODEL`) | идентификатор модели | `deepseek-v4.1-flash` |
| `DATA_DIR` | каталог с `questions.csv` и `knowledge-base.zip` | `data` |
| `TOP_K`, `MAX_WORKERS` | глубина поиска и число потоков | `6`, `4` |
| `TEMPERATURE`, `MAX_TOKENS` | параметры генерации | `0`, `700` |
| `CITE_STYLE` | `ref` — читаемая ссылка, `id` — `[E1]`, `both` — вместе | `ref` |
| `EVENT_DATE` | дата, на которую определяются редакции | сегодня |
| `RETRIEVAL_DENSE` | dense BGE на старте; `0` — BM25 + TF-IDF без сети | `0` |
| `ANSWER_REVIEW` | редакторский проход (0 — выключить) | `1` |
| `ANSWER_MINIMALITY` | дополнительное сокращение ответа | `0` |
| `REVIEW_BUDGET_SECONDS` | бюджет времени на редактуру | `840` |
| `MOCK_LLM=1` | заглушка вместо модели | — |

## Сабмит

Регламент переносит в среду проверки только корневые `.py` и `requirements.txt`,
поэтому `llmguard/` и `prompts/*.md` собираются в плоский архив:

```bash
python3 build_submission.py --check     # тесты, затем сборка
# → dist/psb_legal_assistant.zip, 44 КБ, 9 файлов в корне
```

В архиве: `solution.py`, `retrieval_runtime.py` (ML1), `system_prompt.py` (промпт из
`prompts/system_prompt.md`), пять модулей `llmguard/*.py` и `requirements.txt`
(сторонних зависимостей нет). `.env` в архив не попадает — сборка это проверяет.
Индекс строится на старте из `DATA_DIR/knowledge-base.zip`, готовый индекс не нужен.

## Как формируется ответ

**Доказательства.** `[E1]` — `source_reference`, значимые поля `metadata` (номер, дата,
редакция, статус, пункт) и `text` до 1100 символов. До 6 найденных фрагментов плюс до
3 соседних положений: нужный пункт часто стоит вплотную к найденному.

**Промпт** (`prompts/system_prompt.md`) — статичная часть, доказательства идут отдельным
user-сообщением. Блоки: роль, иерархия инструкций (промпт > evidence > вопрос), запрет
на знания из памяти, процедура привязки тезиса к цитате, ложная посылка, редакции и даты,
4 шаблона отказа, формат (60–150 слов, ссылка после утверждения), самопроверка.

**Валидатор** (`llmguard/validator.py`) до записи в CSV проверяет: `[En]` существуют в
списке доказательств; ссылка есть, если доказательства непустые; нет ложного отказа и
отказ объясняет пробел; числа из ответа есть в доказательствах; нет «как правило» и
«я не юрист»; объём ≤ 180 слов, markdown вычищен. При нарушениях — repair-проход с
перечнем замечаний, при повторном провале — `fallback_refusal()` на первом доказательстве.
Один плохой вопрос не роняет прогон.

**Ссылки.** Модель ставит служебные `[En]`, валидатор их проверяет, а перед записью в CSV
код заменяет метки на читаемую ссылку из метаданных: «(п. 3.1 договора № А-08/2024)»,
«(ст. 70 ТК РФ)». Судья видит источник, маппинг при этом детерминированный.

Ложная посылка с числом опровергается детерминированно: если числа из вопроса нет в
доказательствах, к ответу добавляется преамбула «Посылка в вопросе не подтверждается»,
даже когда модель её пропустила.

## Структура

```
solution.py            точка входа и конвейер
llmguard/evidence.py   RetrievedChunk → [E1..En], диалоги, сигналы посылки
llmguard/validator.py  проверки ответа, fallback
llmguard/verifier.py   редактор полноты/заземлённости и точечный repair
llmguard/editions.py   действующая редакция для датированного вопроса
llmguard/postprocess.py  детерминированная чистка ответа
llmguard/textutil.py   разбиение на предложения
llmguard/prompt_builder.py  сборка сообщений
llmguard/client.py     OpenAI-совместимый клиент и заглушка
scripts/judge_answers.py  локальный LLM-судья по регламенту
build_submission.py    плоский ZIP по техрегламенту
prompts/system_prompt.md   системный промпт (правится здесь)
```
