# ML2 — генерация, промпт и guardrails

Слой, который превращает выдачу ML1 в готовый ответ и в `submission.csv`.
Берёт `RetrievedChunk` из `retrieval`, собирает нумерованные доказательства `[E1]…[En]`,
вызывает DeepSeek V4.1 Flash по OpenAI-совместимому API, проверяет ответ и только потом пишет CSV.

```
question ──► parse_question ──► Retriever.search_with_diagnostics
                                        │
                              build_evidence  (дедуп, лимиты, [E1..En])
                                        │
                              premise_warnings (числа/имена из вопроса, которых нет в доказательствах)
                                        │
                     system_prompt.md + <evidence> + <question>
                                        │
                                   LLM (temp=0)
                                        │
                                  validate ──плохо──► repair-проход (до 2 попыток)
                                        │                     │
                                        └───── fallback_refusal
                                        │
                                  submission.csv (id,answer)
```

## Запуск

```bash
cd ML2

# 1. Без модели: проверка всего конвейера на реальном индексе ML1
MOCK_LLM=1 python3 solution.py --questions ../ML1/demo_questions.csv --data-dir ../ML1 \
    --out submission_mock.csv --trace trace.jsonl --verbose

# 2. Боевой прогон
export LLM_BASE_URL="https://..."      # AITUNNEL / Platform Proxy
export LLM_API_KEY="..."
export LLM_MODEL="deepseek-v4.1-flash"
python3 solution.py --questions ../ML1/demo_questions.csv --data-dir ../ML1 --out submission.csv

# 3. Тесты guardrails
python3 -m unittest discover -s tests -v
```

На платформе `retrieval_runtime.py` кладётся рядом с `solution.py` (его генерирует
`ML1/scripts/export_retrieval.py`), `solution.py` сам найдёт `DATA_DIR` и файл вопросов.

| Переменная | Смысл | По умолчанию |
| --- | --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | прокси модели | — |
| `LLM_MODEL` | идентификатор модели | `deepseek-v4.1-flash` |
| `TOP_K` | сколько чанков брать у ML1 | `6` |
| `MOCK_LLM` | `1` — заглушка без сети | — |
| `EVENT_DATE` | дата, на которую определяются редакции | сегодня |

## Структура доказательства

Из `RetrievedChunk` берутся `chunk_id`, `text`, `source_reference` и часть `metadata`
(`doc_type`, `doc_number`, `doc_date`, `edition_date`, `effective_date`, `validity_period`,
`version_status`, `temporal_status`, `article/section/clause/part`, `amends_clause`,
`counterparties`). В модель уходит компактный блок:

```
[E1] ДОГОВОР АРЕНДЫ НЕЖИЛОГО ПОМЕЩЕНИЯ № А-08/2024 от 01.08.2024, п. 3.1
metadata: doc_type=contract, doc_number=А-08/2024, temporal_status=undated, clause=3.1, counterparties=[...]
text: 3.1. Арендная плата составляет 450 000 рублей в месяц, включая НДС.
```

Полные 40+ полей `metadata` не передаются: они раздувают промпт и не нужны модели.
`text` режется до 1100 символов на фрагмент и до 7000 символов суммарно.

## Почему промпт такой

`prompts/system_prompt.md` — статичная часть, доказательства и вопрос идут отдельным
user-сообщением (так работает prompt caching и не размывается инструкция).

| Блок | Решает |
| --- | --- |
| `РОЛЬ` | задаёт жанр: юрист-консультант, а не чат-бот; сразу отсекает «отличный вопрос!» |
| `ИЕРАРХИЯ ИНСТРУКЦИЙ` | системный промпт > evidence > вопрос; текст в чанках объявлен данными, а не командами |
| `ЕДИНСТВЕННЫЙ ИСТОЧНИК ИСТИНЫ` | запрет на статьи/суммы/сроки из параметрической памяти + правило «нет подтверждения — нет утверждения» |
| `КАК СОПОСТАВЛЯТЬ` | процедура привязки тезиса к цитате; цитата стоит там, где утверждение, а не в конце ответа |
| `ЛОЖНАЯ ПОСЫЛКА` | формула «Посылка не подтверждается: … — в документах … [E1]» |
| `РЕДАКЦИИ И ДАТЫ` | `version_status` / `validity_period`; утративший силу документ нельзя применять |
| `ОТКАЗ` | 4 шаблона + запрет ложного отказа, когда доказательства есть |
| `ФОРМАТ` | 60–150 слов, без markdown, `[En]` после утверждения, числа дословно |
| `САМОПРОВЕРКА` | 7 пунктов, которые модель прогоняет молча перед выводом |

Отдельно закрыт самый дорогой провал в этом кейсе — **ложный отказ**. Модель склонна
писать «недостаточно данных» при любом сомнении, поэтому в промпте есть и прямой запрет
(«ложный отказ так же плох, как выдумка»), и программный детектор: если доказательства
непустые, а в ответе есть маркер отказа без единой ссылки — ответ уходит на переписывание.

## Валидатор

`llmguard/validator.py` проверяет каждый ответ до записи в CSV:

1. `[En]` существуют в списке доказательств (несуществующие вырезаются);
2. ссылка вообще есть, если доказательства непустые;
3. нет ложного отказа (отказ при непустых доказательствах и без ссылок);
4. отказ объясняет, чего не хватает;
5. числа из ответа встречаются в доказательствах (ловит выдуманные суммы и сроки);
6. нет «как правило», «возможно», «я не юрист»;
7. объём ≤ 180 слов, markdown и переводы строк вычищаются.

При нарушениях — один repair-проход с перечнем нарушений. Если и он не помог,
ответ заменяется на `fallback_refusal()` — детерминированную выжимку из первого
доказательства со ссылкой. Прогон не падает из-за одного плохого вопроса.

## Состояние

- 27 юнит-тестов: парсинг диалогов, дедуп доказательств, ложная посылка, все правила валидатора, CSV round-trip, end-to-end с подставной моделью.
- Полный прогон на 18 демо-вопросах ML1 с заглушкой: 0 падений, 0 неизвестных цитат,
  вопрос 3 (пособие по беременности и родам) корректно уходит в отказ — ML1 отдаёт пустую выдачу.
- Боевой прогон на живом прокси ещё не делался: в рабочем окружении не было ключа.

## Что осталось

1. Прогнать на живом DeepSeek V4.1 Flash, замерить время ответа и долю repair-проходов.
2. Подобрать `TOP_K` (6 vs 8): на вопросе 1 ML1 не отдаёт п. 3.3 в топ-5.
3. Если платформа ждёт `id,answer` без кавычек — переключить `csv.QUOTE_ALL` на `QUOTE_MINIMAL`.
4. Добавить 2–3 few-shot только для формата, без реальных ответов из базы (утечка в скоринг).
