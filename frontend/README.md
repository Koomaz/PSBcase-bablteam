# Frontend — веб-чат юридического ассистента

Клиентская часть задачи #5: вопрос → ответ с кликабельными ссылками `[1]…[n]` →
открытие подтверждающего фрагмента документа. Стек и оболочка приложения взяты
из [openai/openai-chatkit-starter-app](https://github.com/openai/openai-chatkit-starter-app)
(MIT): React 19, Vite, TypeScript, Tailwind 4, светлая/тёмная тема. Панель чата
и взаимодействия реализованы поверх нашего API-контракта.

## Состав

| Файл | Назначение |
| --- | --- |
| `src/App.tsx` | оболочка: шапка со статусом сервиса, панель чата, выдвижная панель источника |
| `src/components/ChatPanel.tsx` | состояние диалога, отправка, история, повтор после ошибки |
| `src/components/Message.tsx` | сообщения, плашки статусов, кликабельные цитаты `[1]…[n]` |
| `src/components/SourcePanel.tsx` | источник: документ, положение, редакция/даты, фрагмент |
| `src/lib/api.ts` | клиент API и типы контракта |
| `serve.py` | раздача `dist/` и прокси `/api/*`, `/health/*` на бэкенд (stdlib) |

## Сборка и запуск

```sh
npm install
npm run dev        # разработка: http://127.0.0.1:3000, прокси на :8000
npm run build      # продакшен-сборка в dist/
python serve.py    # http://127.0.0.1:8080 — раздача dist/ + прокси API
```

Переменные: `PSB_API_BASE` — адрес бэкенда для vite-прокси (по умолчанию
`http://127.0.0.1:8000`); `VITE_API_URL` — базовый путь API для собранного
приложения (по умолчанию тот же origin); `PSB_API_URL`, `PSB_FRONTEND_PORT` —
для `serve.py`.

## Контракт, на который опирается клиент

- `POST /api/chat` — `{question, history:[{role, content}]}` → `{kind, answer, sources}`.
  Вопрос до 4000 символов, история до 8 сообщений и 12 000 символов.
- `GET /api/sources/{chunk_id}` — метаданные источника и дословный текст фрагмента.
- `GET /health/ready` — готовность сервиса.
- Ошибки — `{"detail": {"code", "message"}}`; сообщение показывается пользователю
  с кнопкой «Повторить».

Метки `[1]…[n]` в тексте ответа соответствуют порядку элементов `sources`.
Статусы ответа (`kind`): `answer`, `partial`, `clarification`, `insufficient`,
`refusal` — отображаются плашкой над текстом.

## Что реализовано сверх базы стартера

- Кликабельные цитаты `[1]…[n]` в ответе и список источников под сообщением.
- Панель источника: документ, номер, положение (статья/пункт), редакция и даты,
  временной статус, подтверждающий фрагмент из `GET /api/sources/{chunk_id}`.
- Плашки статусов: частичный ответ, уточнение, недостаточно данных, отказ.
- История диалога: последние 8 сообщений передаются в `history` каждого запроса.
- Ошибка API с понятным сообщением и кнопкой «Повторить».
- Статус сервиса в шапке (проверка `/health/ready` при загрузке).
