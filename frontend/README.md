# Frontend — веб-чат юридического ассистента

Клиентская часть задачи #5: вопрос → ответ с кликабельными ссылками `[1]…[n]` →
открытие подтверждающего фрагмента документа. Без сборщиков и фреймворков:
статический HTML/CSS/JS плюс небольшой локальный сервер с прокси API.

## Состав

| Файл | Назначение |
| --- | --- |
| `index.html` | страница: чат, панель источника |
| `app.js` | состояние диалога, вызовы API, рендер цитат и источников |
| `style.css` | оформление |
| `serve.py` | раздача статики и прокси `/api/*`, `/health/*` на бэкенд (stdlib) |

## Запуск

Сначала поднимите бэкенд (ветка `backend/psb-integration`, раздел «API для чата»):

```sh
python -m uvicorn web_api:app --host 127.0.0.1 --port 8000
```

Затем из каталога `frontend/`:

```sh
python serve.py
# http://127.0.0.1:8080
```

Переменные: `PSB_API_URL` (адрес бэкенда), `PSB_FRONTEND_PORT` (порт страницы).
При отдельной раздаче статики (например, через `python -m http.server`) укажите
origin страницы в `PSB_CORS_ORIGINS` бэкенда или откройте страницу с параметром
`?api=http://127.0.0.1:8000`.

## Контракт, на который опирается клиент

- `POST /api/chat` — `{question, history:[{role, content}]}` → `{kind, answer, sources}`.
  Вопрос до 4000 символов, история до 8 сообщений и 12 000 символов.
- `GET /api/sources/{chunk_id}` — метаданные источника и дословный текст фрагмента.
- `GET /health/ready` — готовность сервиса.
- Ошибки — `{"detail": {"code", "message"}}`; сообщение показывается пользователю.

Метки `[1]…[n]` в тексте ответа соответствуют порядку элементов `sources`.
Статусы ответа (`kind`): `answer`, `partial`, `clarification`, `insufficient`,
`refusal` — отображаются плашкой над текстом.

## Что уже работает

- Отправка вопроса, индикатор обработки, ответ с кликабельными цитатами.
- Список источников под ответом; панель источника с документом, положением,
  редакцией/датами и подтверждающим фрагментом.
- Учёт истории диалога (последние 8 сообщений).
- Плашки статусов: уточнение, частичный ответ, недостаточно данных, отказ.
- Ошибка API с понятным сообщением и кнопкой «Повторить».
- Статус сервиса в шапке (проверка `/health/ready` при загрузке).
