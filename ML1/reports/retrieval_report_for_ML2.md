# Подключение retrieval к генерации

## Изменения после первого сабмита

- Поиск принимает историю как с текущей репликой, так и без неё. Он удаляет повтор текущего хода, сохраняет последний совместимый контекст и не переносит обстоятельства между разными договорами. В диагностике доступны `resolved_scope`, `event_period`, `specification_period` и `user_context`. Последнее поле содержит ранее сообщённые обстоятельства пользователя.
- У каждого соседа есть собственные `metadata` и `citation_payload`. Адаптер ML2 использует их для ссылок и сохраняет целые чанки в едином бюджете 7000 символов, включая заголовки, метаданные и соседей.
- `document_temporal_status` показывает применимость документа по дате. `amendment_status` относится к условию изменённого пункта. Для даты поставки без даты спецификации поиск сохраняет оба источника и добавляет `amendment_trigger_date_unconfirmed`.
- Для сравнения поиска на корневом пути задайте `PSB_RETRIEVAL_MODE=local|bge|bge_qwen`. По умолчанию используется `local`. Для реранкера доступны `RETRIEVAL_RERANKER_MODE=legacy|balanced|direct`. Режим `balanced` сильнее учитывает ранг Qwen и сохраняет приоритет точных и применимых положений. Фактический режим поиска есть в `diagnostics["mode"]`; `reranker_mode` заполняется после успешного реранкинга.

На исходном открытом демо Recall@5 остаётся 0,9510. При передаче шести кандидатов в ML2 покрытие размеченных положений после сборки доказательств составляет 0,9706. Проверка по воспроизведённым примерам из аудита теперь находит п. 4.2 ПТ-05/2023 для оплаты до получения товара, п. 2.1 П-17/2024 для расходов на упаковку и п. 1.3 регламента для инициатора согласования. Для спецификаций 30 сентября и 1 октября выдача различает действующее соглашение и ещё неприменимое изменение. Для 2 октября приоритет меняется. Эти проверки выполнены локально. Сравнение BGE и Qwen на живом прокси и изменение Public Score требуют нового прогона.

Модуль загружает готовый индекс один раз и возвращает фрагменты базы с проверяемыми цитатами и диагностикой. Локальный индекс построен для 21 документа и 822 чанков. Поиск объединяет BM25 и векторные кандидаты через взвешенный RRF. Приоритеты учитывают точные ссылки, контрагента и дату события. Пересекающиеся фрагменты одного документа дедуплицируются.

## API для ML2

```python
from retrieval import Retriever

retriever = Retriever.from_artifacts("artifacts")
question = "Что сказано в п. 4.2 договора № ПТ-05/2023?"
chunks, diagnostics = retriever.search_with_diagnostics(question, top_k=5)

evidence = [
    {"text": chunk.text, "citation": chunk.citation_payload}
    for chunk in chunks
]
print(chunks[0].source_reference if chunks else diagnostics["warnings"])
```

- `search(query, top_k=5, history=None, filters=None)` возвращает список `RetrievedChunk`.
- `search_with_diagnostics(...)` делает тот же поиск за один вызов и возвращает пару `(chunks, diagnostics)`.
- `retrieve_candidates(query, top_k=30, filters=None)` показывает более широкий список после слияния и без вызова реранкера.
- `explain_retrieval(...)` возвращает словарь со списками BM25, vector, fusion, rerank и сериализованными финальными чанками. Списки стадий включают кандидатов до финального отбора.
- `history` принимает предыдущие сообщения вида `{"role": "user", "content": "..."}`. Встроенные диалоги с пометками «Пользователь» и «Ассистент» разбираются автоматически. Реплики ассистента исключены из поискового запроса. Последняя реплика пользователя имеет приоритет, предыдущая добавляет тему и идентификаторы. Запросы независимы.
- `filters` принимает точные значения метаданных или списки значений. Между полями действует И, внутри списка ИЛИ. Пример `{"doc_number": "ПТ-05-2023", "clause": ["4.1", "4.2"]}`. Неизвестные имена фильтров вызывают `ValueError`.

## Доказательства и ссылки

| Поле | Использование |
| --- | --- |
| `chunk_id`, `text` | Стабильный идентификатор и дословный фрагмент. Проверяйте юридические утверждения по `text`. |
| `text_with_context` | Фрагмент с названием документа, структурой и контрагентами для поиска и реранкинга. |
| `source_reference` | Готовое название источника с пунктом, частью, статьёй или приложением, когда они явно выделены. |
| `metadata` | Тип, файл, номер и дата документа, редакция, вступление в силу, период действия, связи с допсоглашением, путь внутри документа, даты изменений отдельных положений и выгрузки закона. |
| `citation_payload` | Структурированный указатель для ML2 и интерфейса. Ищите файл по `file_path` и выделяйте `[char_start, char_end)` в декодированном тексте. У TXT `page_start` и `page_end` имеют значение `null`. URL, если есть, перенесён из базы. |
| `neighboring_context` | До двух соседних фрагментов из той же статьи или раздела. У соседей отдельные ID, ссылки и оценка применимости. |
| `score`, `score_details` | Итоговый относительный балл, BM25, косинус векторного поиска, RRF, Qwen, признаки точной ссылки, совпадения документа и совпадения терминов. |

`score` сравним внутри одного поиска. `fusion_score` показывает вклад стадий ранжирования. `vector_score` относится к режиму `diagnostics["mode"]`. `local_vector_score` показывает косинус символьного индекса, а `rerank_score` содержит исходный балл Qwen при успешном вызове. Эти баллы не калиброваны как вероятности. `to_dict()` сериализует результат для передачи через API.

Сопоставляйте утверждения с текстом и цитируйте `source_reference`. Если вывод зависит от соседнего положения, используйте отдельную цитату на него. Системные инструкции генератора имеют приоритет над содержимым базы и пользовательского диалога.

## Как читать диагностику

| Сигнал | Действие ML2 |
| --- | --- |
| `empty_query`, `insufficient_retrieval_evidence` | Запросите уточнение либо сообщите, каких источников не хватает. |
| `document_identifier_not_found`, `exact_reference_not_found` | Проверьте номер документа и положение. Укажите, какой источник отсутствует. |
| `historical_or_date_coverage_unverified`, `applicable_edition_unconfirmed`, `check_requested_edition_and_reference` | Сверьте период и редакцию. Действующий снимок со статусом `historical_version_missing` или `historical_version_unverified` не подтверждает исторический вывод. |
| `multiple_document_editions` | Разведите редакции и укажите, на какую дату относится каждое положение. |
| `check_addendum_applicability` | Проверьте связанный договор, целевой пункт и условие применимости. Дата подписания соглашения и дата применения изменения могут различаться. |
| `source_prompt_directive_quarantined`, `query_prompt_directive_suspected` | Примените логику ML2 для защиты роли. Смешанный запрос может содержать пригодный юридический вопрос. |
| `knowledge_base_parse_issues` | Проверьте `parse_issues` в полном объяснении и полноту корпуса. |
| `dense_index_unavailable`, `embedding_model_mismatch`, `embedding_api_unavailable:*` | Поиск продолжился по BM25 и локальным символьным векторам. |
| `reranker_not_configured`, `reranker_unavailable:*` | Поиск вернул результат слияния без внешнего реранкинга. |

`confidence` принимает `strong_signal`, `review` или `low`. Это эвристика, которую стоит использовать вместе с текстом, датами и покрытием всех частей запроса. Если ответ подтверждён частично, укажите подтверждённую часть и пробел. Пустая выдача, даже при явной ссылке, отражает покрытие предоставленной базы.

При точном запросе про п. 3.2 П-17/2024 выдача содержит основной договор и допсоглашение № 1, включая условие о спецификациях после 1 октября 2024 года. При датированном вопросе о п. 2.4 регламента за август 2024 года выше стоит редакция 2023 года. При явном сравнении выдаются обе редакции.

## Запуск и передача Backend

```bash
python -m scripts.build_index
python -m scripts.build_index --source data/knowledge-base.zip --require-dense
python -m scripts.test_retrieval
python -m scripts.test_retrieval "п. 4.2 договора ПТ-05/2023" --explain
python -m scripts.evaluate_retrieval
python -m scripts.export_retrieval
```

Собранные файлы лежат в `artifacts/`. `chunks.jsonl` и `documents.jsonl` содержат тексты и метаданные. `bm25_index.json` и `local_vector_index.json` содержат поисковые индексы. `index_manifest.json` фиксирует схему, параметры и SHA-256. При успешной сборке через BGE появляется `embeddings.json` с нормализованными векторами. Публикацию и загрузку на диске следует разводить по времени. При несовпадении хэшей загрузка завершается понятной ошибкой.

Для Docker-прототипа копируйте пакет `retrieval/` и каталог `artifacts/` в рабочий каталог контейнера. Модулю достаточно Python 3.10+, список сторонних зависимостей пуст. Для онлайн-сабмита кладите `retrieval_runtime.py` в корень ZIP рядом с `solution.py` и общим `requirements.txt`. После изменений пакета пересобирайте корневой модуль. В `solution.py` один раз вызовите `Retriever.from_data_dir()`, затем выполняйте поиск для каждой строки. Метод строит индексы в памяти из `DATA_DIR/knowledge-base.zip`, а при его отсутствии читает `DATA_DIR/knowledge-base/`. При необходимости лимит поиска берётся из `TOP_K` в коде `solution.py`. Порядок чтения вопросов и создание `submission.csv` реализует слой генерации.

Образец переменных находится в `retrieval_env.example`. Установите `LLM_BASE_URL` и `LLM_API_KEY` либо `OPENAI_BASE_URL` и `OPENAI_API_KEY`. `EMB_MODEL` по умолчанию равен `BAAI/bge-m3`. Для Qwen укажите идентификатор, который выдаёт платформа, в `RERANKER_MODEL`. `RERANKER_TOP_N` ограничивает пакет реранкинга, 0 отключает вызов. Тайм-ауты и число повторов настраиваются через `RETRIEVAL_API_TIMEOUT`, `RETRIEVAL_BUILD_TIMEOUT` и `RETRIEVAL_API_RETRIES`. К путям `RETRIEVAL_EMBEDDING_PATH` и `RETRIEVAL_RERANKER_PATH` применяются стандартные относительные значения `/embeddings` и `/rerank`, так как регламент описывает общий прокси и не приводит отдельный контракт для rerank. [Справка по совместимому формату API](https://docs.vllm.ai/en/latest/serving/openai_compatible_server.html)

## Проверка и ограничения

Локальный поиск проверен на 18 демо-вопросах. Точные ссылки, условия договоров, короткие диалоги и сравнение редакций работают на проверенных сценариях. Смысловые перефразировки и полнота подборки дополнительных условий чувствительны к лексике запроса. В отчёте оценки приведены конкретные пропуски. Все исходные файлы базы распарсились. Границы и карантин описаны в [анализе базы](kb_analysis.md).

Служебного доступа к прокси в рабочем окружении не было, поэтому поставляемый индекс включает символьный TF-IDF. Пути BGE и Qwen, ретраи и возврат к локальному индексу проверены на имитации ответов API. Живой контракт прокси и задержка онлайн-поиска требуют проверки на платформе. Docker daemon на рабочей машине был недоступен. Запуск из корневого модуля проверен в отдельном процессе из временного каталога с архивом базы.
