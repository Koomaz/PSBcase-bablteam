# PSBcase-bablteam

Юридический ассистент для кейса ПСБ на Hack&Change 2026. Помогает юристу находить применимые положения в предоставленной базе знаний, получать ответы с проверяемыми источниками и уточнять недостающие сведения.

Основной сценарий: вопрос → поиск документов → ответ с основанием → проверка подтверждающего положения. При выборе источников учитываются контрагент, договор, дата события и редакция документа.

| `ML2/` | Генерация, проверки ответов, обработка диалогов и сборка сабмита | [ML2: запуск и конфигурация](ML2/README.md) |

Контракт выдачи поиска и поля ссылок описаны в [инструкции подключения ML1 к генерации](ML1/reports/retrieval_report_for_ML2.md). Результаты оценки поиска находятся в [отчёте ML1](ML1/reports/evaluation_report.md).

## Требования и конфигурация

- Python 3.10+; текущие ML-модули используют стандартную библиотеку Python.
- Для локальной проверки поиска доступны индексы в `ML1/artifacts/` и вопросы в `ML1/demo_questions.csv`.
- Для генерации с рабочей моделью нужны доступ к совместимому API и значения `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. На платформе их предоставляет конфигурация организаторов; локально значения задаются в окружении или `ML2/.env`.
- Настройки эмбеддингов и реранжирования описаны в [примере конфигурации ML1](ML1/retrieval_env.example); настройки генерации — в [README ML2](ML2/README.md).

В автоматической проверке и финальном прототипе используется модель из технического регламента — DeepSeek V4.1 Flash. Идентификатор для API берётся из конфигурации. Локальная конфигурация `ML2/.env` исключена из Git.

## Локальный прогон

Команды ниже выполняются из корня репозитория.

Проверка конвейера с заглушкой модели:

```bash
MOCK_LLM=1 python3 ML2/solution.py --questions ML1/demo_questions.csv --data-dir ML1 --out ML2/submission_mock.csv --trace ML2/trace_mock.jsonl
```

Прогон с рабочей моделью после настройки доступа к API:

```bash
MOCK_LLM=0 python3 ML2/solution.py --questions ML1/demo_questions.csv --data-dir ML1 --out ML2/submission.csv --trace ML2/answers_trace.jsonl
```

В стартовом логе проверьте активный режим: при отсутствии настроек API клиент автоматически выбирает заглушку. Режим прогона фиксируется в [таблице приёмки](docs/acceptance.md). Результат сохраняется в CSV с колонками `id,answer`; трассировка содержит ID ссылок, число доказательств, замечания валидатора и время обработки. Для проверки ссылок сохраните также фактический набор документов и фрагментов, переданный в модель для каждого вопроса.

## Проверки и сабмит

Проверки слоя генерации и сборка ZIP для платформы:

```bash
python3 -m unittest discover -s ML2/tests -v
python3 ML2/build_submission.py --check
```

Архив создаётся в `ML2/dist/psb_legal_assistant.zip`. Сборщик размещает Python-модули и `requirements.txt` в корне архива. При запуске на платформе индекс строится из предоставленного `DATA_DIR/knowledge-base.zip`.

Для полной проверки ML1 распакуйте базу организаторов в `ML1/knowledge-base/` и выполните:

```bash
python3 ML1/scripts/test_retrieval.py
```

Инструкции пересборки индекса приведены в [README ML1](ML1/README.md). Продуктовая проверка содержания, полноты и применимости ответов ведётся в [таблице приёмки](docs/acceptance.md); программные проверки валидатора фиксируются отдельно.
